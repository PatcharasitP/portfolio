## ผลการวัด

- First Contentful Paint **88 ms** เน็ตเร็ว และ **268 ms** เน็ตมือถือจำลอง (1.6 Mbps, CPU ช้าลง 4 เท่า) วัดบนเว็บจริง มัธยฐาน 5 รอบ ไม่มีไลบรารีภายนอก
- ฟอนต์ Sarabun ของเราเอง 3 น้ำหนัก รวม 50 KB (ย่อเหลือเฉพาะตัวอักษรที่เว็บใช้) ทุกเครื่องเห็นฟอนต์เดียวกัน เดิมประกาศชื่อไว้แต่ไม่ได้โหลด คนเปิดบน Windows จึงเห็นอีกฟอนต์
- ความสูงหน้า 4,356 px (ก่อนปรับให้พับเคสได้คือ 10,428 px)
- เทสอัตโนมัติ `python3 tests/browser_separators.py` อ่านข้อความบนจอจริงทั้งสองภาษา รวมตัวที่ CSS วาดเอง ห้ามมีจุดกลางหรือขีดคั่น
- เทสอัตโนมัติ `python3 tests/browser_page.py` เปิดหน้าจริง 8 จอ (สองภาษา สองขนาด สองธีม) ภาพครบทุกผลงาน ตัวเลขจบที่ค่าจริง ไม่มี error ไม่มีเลื่อนข้าง ใส่ `PF_BASE=<url>` เพื่อยิงเว็บจริง
- เทสอัตโนมัติ `python3 tests/browser_fonts.py` ตัวอักษรที่วาดจริงต้องมาจากไฟล์ Sarabun ของเรา และทุกตัวบนจอต้องมีในฟอนต์
- เทสอัตโนมัติ `python3 tests/browser_gates.py` ด่านหน้าตา 16 ด่านจากหน้าจริง 32 ชุด (8 ความกว้าง สองภาษา สองธีม) ใช้ตัววัดกลาง `Scripts/ui_gates` ของ workspace
- กฎดีไซน์ทั้งหมดของเว็บนี้อยู่ใน [`DESIGN.md`](DESIGN.md)

## โครงสร้าง

```
Portfolio/
├── DESIGN.md           ระบบดีไซน์และกฎที่มีเทสบังคับ อ่านก่อนแก้หน้าจอ
├── index.html          โครงหน้า + โทเคนดีไซน์ + CSS ทั้งหมด (inline ไม่ต้องรอไฟล์นอก)
├── src/
│   ├── content.js      เนื้อหาทั้งเว็บ สองภาษาในไฟล์เดียว แก้ที่นี่ที่เดียว
│   ├── app.js          วาดหน้าจากเนื้อหา + สลับภาษา/โหมดสี + ตัวเลขนับขึ้น
│   └── art.js          ภาพเส้นบางประจำผลงาน (id ของผลงานต้องมีภาพ เทสเช็ค)
├── tests/              เทสเปิดหน้าจริงด้วย Playwright
├── tools/build-fonts.py  สร้างฟอนต์ Sarabun ฉบับย่อจากตัวอักษรที่เว็บใช้จริง
└── assets/             รูปโปรไฟล์, ภาพพรีวิวตอนแชร์, ไฟล์ CV, ฟอนต์ (fonts/ สัญญาอนุญาต OFL)
```

## แก้เนื้อหา

เปิด `src/content.js` แล้วแก้ได้เลย ทุกข้อความมีคู่ `th` / `en` อยู่ติดกัน
เพิ่มโปรเจกต์ใหม่ = เพิ่ม object ใน `projects` โดยใส่ `period` (ช่วงเวลา), `impact` (ผลลัพธ์ 1 บรรทัด) หรือ `results` (ผลลัพธ์เป็นข้อ) และ `carl` (4 หัวข้อ) แล้วเพิ่มภาพใน `src/art.js` ด้วย id เดียวกัน ให้ครบทั้งสองภาษา

## Dashboard: วิเคราะห์เรื่องร้องเรียนกรุงเทพฯ

`dashboard/` ชิ้นงานวิเคราะห์ข้อมูลเปิดของกรุงเทพมหานคร (Traffy Fondue) 54,056 เรื่อง
เล่าเรื่อง 6 ตอน พร้อมแผนที่ 50 เขต ทำงานในเบราว์เซอร์ล้วน ไม่ต้องมีเซิร์ฟเวอร์

**ทำไมต้องสร้างใหม่แทนที่จะโชว์งานบริษัท:** งานวิเคราะห์ในที่ทำงานเป็นข้อมูลลับ
จึงตั้งโจทย์แบบเดียวกันกับข้อมูลสาธารณะ เพื่อโชว์วิธีคิดโดยไม่แตะข้อมูลของใคร

**ขั้นตอน:** ดึง CSV 100 MB → ทำความสะอาดด้วย pandas → สรุปเป็นไฟล์ JSON รวม 50 KB
→ แสดงผลด้วย Vega-Lite ที่โหลดเมื่อผู้ใช้เลื่อนใกล้กราฟเท่านั้น

**บทเรียนระหว่างทางที่บันทึกไว้:**
- ชื่อเขตในข้อมูลกับในแผนที่ราชการสะกดต่างกันหนึ่งตัว (ฎ ชฎา กับ ฏ ปฏัก) ทำให้เชื่อมข้อมูลขาดไปหนึ่งเขต
  โดยไม่มี error ใด ๆ ต้องตรวจจำนวนที่จับคู่ได้ทุกครั้ง ไม่ใช่ดูแค่ว่าโค้ดรันผ่าน
- อายุงานค้างต้องคิดจากวันล่าสุดในชุดข้อมูล ไม่ใช่วันที่เปิดดู มิฉะนั้นทุกเรื่องจะดูค้างนานเท่ากันหมด
- vega-embed ตั้ง `display:inline-block` ให้กล่องที่วาด ทำให้ `width:"container"` วัดได้ 0
  แล้ววาดกราฟกว้าง 0 px ทั้งหมด เทสที่นับจำนวน canvas อย่างเดียวจับไม่เจอ ต้องตรวจความกว้างจริงด้วย
- กราฟแท่งที่แกนไม่เริ่มจากศูนย์ทำให้แท่งลากทะลุกรอบและบิดเบือนการรับรู้ จึงเปลี่ยนเป็น lollipop
